# 最早期项目的回顾

## 文件介绍

- **ALU/gate.py** — 用 numpy 感知机（权重 + 偏置）实现的基本逻辑门：AND、NAND、OR、NOR、XOR、NOT
- **ALU/full_adder.py** — 由门电路组合出的半加器、一位全加器，以及支持任意位数的加法器（通过初始进位 CI 可实现减法）
- **README.md** — 只有标题，还没写内容



## 位置评估

**组合逻辑层面的便利性缺口**（都能用现有门搭出来，但建议封装成独立函数）：

- **XNOR**：等值比较的核心，比较器、Zero 标志位会用到
- **多输入门**（3 输入以上的 AND/OR）：现在全是 2 输入，级联虽然可行但代码会很啰嗦
- **MUX（数据选择器）和译码器**：寄存器堆的读写选择、指令译码、ALU 运算类型选择都靠它们，是 CPU 里用量最大的部件



从完备性角度看，`gate.py` 里的 AND、OR、NOT 本身就是功能完备集（任意布尔函数都能由它们组合出来），而且已经有了 NAND、NOR、XOR 这些部件，XOR 加法器、比较器都用得上。每个门的权重和偏置，真值表都是正确的，写半加器/全加器没问题。

**根本性缺口——时序电路**： 现在的门都是无状态的组合逻辑，用函数调用组合就行。但寄存器、程序计数器（PC）、时钟这些需要**反馈回路和状态保持**，也就是锁存器（SR latch）→ D 触发器这一层。这在 Python 里没法靠递归调用门函数实现（会无限循环），必须换一种建模方式：引入显式的状态变量 + 时钟节拍驱动的更新。



# 从“组合逻辑”到“时序逻辑”

## 一、当前的缺陷：缺的不是门，是“时间”

`gate.py` 里所有函数都是**纯函数**：输出只由当前输入决定，`AND(1,0)` 永远返回 0，不管你以前调用过它什么。这叫组合逻辑——**没有记忆**。

但 CPU 的本质是状态机：寄存器的值、PC 的值、标志位，都是“**过去**输入留下的结果”。要存储 1 bit，电路必须满足：**输出依赖于自己过去的输出**。而实现这件事的唯一电路手段就是**反馈回路**——把输出接回输入。

如 `full_adder.py`：`full_adder_one` 调 `semi_adder_one`，`semi_adder_one` 调 `XOR`/`AND`，信号一路向下，永不回头。整个依赖关系是一张**有向无环图（DAG）**。DAG 有拓扑序，所以能算完。而存储恰恰需要**环**。缺陷就在这：当前的建模方式（函数组合）只能表达 DAG，表达不了环。

## 二、为什么 Python 递归调用实现不了反馈

SR 锁存器（存储 1 bit 的最底层电路）是两个 NOR 门交叉耦合：

```
Q  = NOR(R, Q̄)
Q̄  = NOR(S, Q)      ← Q̄ 读 Q，Q 读 Q̄，互相咬合
```

直觉的翻译是“既然 Q 的表达式里有 Q̄，那就递归调用求它”：

```python
def q_out(s, r):
    return NOR(r, qbar_out(s, r))   # 求 Q 前必须先拿到 Q̄ 的值

def qbar_out(s, r):
    return NOR(s, q_out(s, r))      # 求 Q̄ 前必须先拿到 Q 的值

q_out(0, 0)   # RecursionError: maximum recursion depth exceeded
```

死锁的原因可以从两层理解：

**语言层：Python 是急切求值的。** 调用 `NOR(r, x)` 之前，参数 `x` 必须已经是一个具体的值。而这里 `x` 的值要等另一个函数返回才能确定，那个函数又反过来等它。每次递归调用都往栈上压一帧“我等着要一个还不存在的值”，没有任何一帧能返回，栈就爆了。

**数学层：这是方程组，不是定义式。** `Q = NOR(R, NOR(S, Q))` 是一个**联立方程**，Q 是它的解（而且有两个稳定解，这正是锁存器能存 0 或 1 的原因）。而函数定义是“已知输入算输出”的单向推导。递归调用试图把方程当定义式展开，自然是无限展开。

**真实电路为什么可以？** 因为硬件和软件的运行模型完全不同：

|          | 真实电路                                                   | Python 函数调用                    |
| -------- | ---------------------------------------------------------- | ---------------------------------- |
| 工作方式 | 所有门**同时、连续**地工作                                 | 语句**串行**执行                   |
| "导线"   | 任意时刻都有确定的电压（上一次稳定后的值）                 | 变量在没有表达式算完之前**没有值** |
| 时间     | 连续的物理时间，门有传播延迟                               | 只有调用顺序，没有"上一时刻"的概念 |
| 反馈     | 环里的旧电压就是天然的"记忆"，回路在纳秒级重新收敛到稳定态 | 环 = 循环依赖 = 无法求值           |

**硬件反馈环里能“咬合”，是因为导线上躺着上一次的旧值；而 Python 变量不是导线，函数调用要求值在调用前就绪。** 

可能会想到用迭代不动点模拟“回路逐渐稳定”（`q_new = NOR(r, q_old)` 反复算到收敛）——这确实是门级仿真器的做法，但它模拟的是纳秒级的物理过程，而且依然没有回答“什么时候算一次状态更新”，这个“等稳定后再采样”的约定，在真实 CPU 里就叫**时钟**。

## 三、怎么做：显式状态变量 + 时钟驱动更新

核心思想：**把硬件里隐式的“延迟/旧值”变成软件里显式的变量。** 具体就是每个有状态的部件都拆成两个量：

- **当前状态 `q`** —— 对应“导线上现在的电压”，就是被显式保存下来的“过去的输出”
- **下一状态 `next`** —— 组合逻辑基于 `q` 算出来的结果

时钟节拍（tick）做且只做一件事：**算完所有人的 next，然后统一提交** `q = next`。这个“current/next 二分 + 统一提交”就是 D 触发器的行为本质——时钟沿采样、其余时间保持。注意我们建模的是触发器的**行为**，而不再用 NOR 门搭它的**结构**（那个交叉耦合环被抽象掉了）。这是层级的跃迁：从门级到寄存器传输级（RTL）。

**最小实现——D 触发器：**

```python
class DFlipFlop:
    def __init__(self, init=0):
        self.q = init        # 显式状态变量："导线上现在的电压"
        self._next = init    # 时钟沿到来时将要写入的值

    def d(self, value):      # 数据输入（组合逻辑随时调用）
        self._next = value

    def tick(self):          # 时钟沿：所有采样结束，统一翻转
        self.q = self._next
```

**规模放大——寄存器和整个 CPU 用同一套纪律：**

```python
class CPU:
    def __init__(self, program):
        self.pc = 0                    # ┐
        self.regs = [0] * 8            # ├ 全部状态，显式摆在变量里
        self.flags = 0                 # │（内存 self.mem 同理）
        self.mem = list(program)       # ┘

    def step(self):                    # 一个时钟节拍
        instr = self.mem[self.pc]     # ① 读：只读当前状态
        next_pc, next_regs, next_flags = self.execute(instr)          # ② 算：纯组合逻辑（你的 full_adder 就活在这里）
        self.pc, self.regs, self.flags = next_pc, next_regs, next_flags      # ③ 提交：时钟沿，原子更新
```

**为什么必须“算完再统一提交”，而不能边算边改？** 举个反例：交换两个寄存器 `A↔B`，如果直接 `self.regs[0] = self.regs[1]; self.regs[1] = self.regs[0]`，第二条读到的是已覆盖的新值，交换失败。正确做法是把 `next_regs` 算成一份完整副本再整体赋值。这不是实现技巧，而是**对真实硬件的忠实模拟**：边沿触发的触发器在整个周期内输出旧值，只在时钟沿瞬间翻转，所以同一拍内“读到的永远是旧值、写的都在沿上生效”。Verilog 里阻塞赋值 `=` 和非阻塞赋值 `<=` 的区别就是在强制这条纪律。

**对应关系总结：**

| 硬件概念                       | 软件对应物                    |
| ------------------------------ | ----------------------------- |
| 导线上的电压（反馈环里的旧值） | 状态变量 `self.q`             |
| 门稳定所需的时间               | 无需模拟，被抽象掉            |
| "等稳定后再采样"的约定         | `tick()` 被调用的时机         |
| 时钟沿                         | `q = next` 的统一提交         |
| 组合逻辑网络                   | `step()` 里①②之间的纯函数部分 |

至于现有的 `gate.py` 和 `full_adder.py`，它们并不浪费，原封不动成为 `step()` 第②步里的组合逻辑。要补的只是上面这层“骨架”。如果想做完全门级、连锁存器内部交叉耦合都仿真的东西，那需要的是事件驱动仿真器（Verilog 仿真器干的事，值 + 事件队列 + 收敛判断），但对 mock CPU 来说，时钟粒度的行为建模是正确的抽象层级。
